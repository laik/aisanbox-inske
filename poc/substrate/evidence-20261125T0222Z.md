# Substrate 第二轮实测证据（resume / 多 actor / 出口凭证注入）

时间：2026-11-25T02:22Z（集群 `k8s-221`，`vm01` 上执行）
前置：`ate-system` 已装好（见 `evidence-20261124T1026Z.md`），`counter` demo 已跑通。
远端环境：`export KUBECONFIG=/etc/kubernetes/admin.conf; export PATH=/root/bin:$PATH`

## A. suspend → resume 恢复状态（上一轮没跑通的那步）

```console
$ kubectl ate create actor poc-a2 -a ate-demo-counter --template counter
$ kubectl ate resume actor poc-a2 -a ate-demo-counter
$ kubectl ate proxy actor poc-a2 -a ate-demo-counter &     # 127.0.0.1:8000
$ curl -X POST http://127.0.0.1:8000/                      # ×2
preserved memory count: 1 | preserved file counter: 1 | preserved rootfs counter: 1
preserved memory count: 2 | preserved file counter: 2 | preserved rootfs counter: 2
$ kubectl ate suspend actor poc-a2 -a ate-demo-counter
ACTOR_STATE_SUSPENDED
$ kubectl ate resume actor poc-a2 -a ate-demo-counter
resume API elapsed: 671 ms
$ curl -X POST http://127.0.0.1:8000/                      # resume 后第一次调用
preserved memory count: 3 | preserved file counter: 3 | preserved rootfs counter: 3
```

要点：内存、文件、rootfs 三处状态都跨 suspend/resume 保留；恢复即续上计数，没有从 0 开始。
上一轮的 `Aborted: another operation is in progress` 是当时有 worker 处于 `WORKER_STATE_UNAVAILABLE`，
不是生命周期本身的问题；本轮 resume 全部成功（只有 resume 会把 actor 放上 worker）。

## B. 一个 WorkerPool 挂多个 actor（用户问的「多个 agent」）

```console
$ for i in 1..6: kubectl ate create actor poc-b$i -a ate-demo-counter --template counter
$ kubectl ate get actors -a ate-demo-counter | awk '$5=="ACTOR_STATE_RUNNING"' | wc -l
1                       # 只有 poc-a2 在跑；其余 6 个 SUSPENDED 不占 worker
$ kubectl ate get workers -a ate-demo-counter
NAME                     WORKER STATE      ACTOR
counter-5b468d9d8c-nz9j5 WORKER_STATE_ACTIVE ate-demo-counter/poc-a2   # 1 个 worker 只服务 1 个 actor
```

worker 被占满时调用其它 actor：

```console
$ kubectl ate resume actor poc-b1 -a ate-demo-counter
error: ... no worker has room for the actor
```

把在跑的 actor 挂起后再依次调用：

```console
$ kubectl ate suspend actor poc-a2 -a ate-demo-counter
$ for a in poc-b1 poc-b2 poc-b3: resume + curl + suspend
poc-b1 -> preserved memory count: 2
poc-b2 -> preserved memory count: 2
poc-b3 -> preserved memory count: 2
$ kubectl ate get actors ... | grep -c ACTOR_STATE_RUNNING
0
```

要点：actor 与 worker 是 **1:1（运行期）**，池子规模 = 可并发运行的 actor 数；
不运行的 actor 只有元数据成本。每个 actor 各自有快照，互不干扰。

## C. 出口策略 + 真实凭证替换（OpenShell provider 平面的对照）

新建第二个 demo（`egress` actor 会对给定 URL 发请求）：

```console
$ ate-setup deploy demo egress --rollout-timeout 6m
Error: waiting for deployment/egress ... (last status: 0/2 replicas available)   # 同 counter 的鸡生蛋
$ kubectl ate create atespace ate-demo-egress                                   # 先建 atespace
$ kubectl -n ate-demo-egress patch deploy egress --patch-file /root/poc/patch-egress.json  # sysctls + CA
$ kubectl -n ate-demo-egress create configmap poc-registry-ca --from-file=ca-certificates.crt=/etc/ssl/certs/ca-certificates.crt
（重建 pod 后）egress-6f6fdf87f6-ld7sv 1/1 Running
$ ate-setup deploy demo egress --rollout-timeout 3m
GOLDEN TAG 77bc21a3-d689-43e0-a2bf-83402fae646c
```

集群侧两处授权/密钥：

```console
$ kubectl create namespace ns1
$ kubectl -n ns1 create secret generic example-api --from-literal=token=test-github-token
$ kubectl -n ate-system get configmap k8s-credential-provider-namespace-policy -o yaml | sed -n '/data:/,/kind:/p'
data:
  namespace-policy.yaml: |
    policies:
    - atespace: ate-demo-egress
      allowedNamespaces:
      - ns1
$ kubectl -n ate-system rollout restart deployment/k8s-credential-provider   # 策略只在启动时加载
```

actor 的出口策略（`kubectl-ate create egress-policy <actor> -a <atespace> -f -`）：

```yaml
rules:
- http:
    hostnames: ["whoami.egress-target.svc.cluster.local"]
    ports: {numbers: [8080]}
    effects:
      replaceHeaders:
      - header: traceparent
        prefix: "tp-"
        credentialUri: "ate-secret://k8s.io/default/ns1/example-api/token"
```

目标：`traefik/whoami`（会回显收到的请求头），先 `crane cp` 到私仓。

正向（actor 只发占位值）：

```console
$ curl -X POST http://127.0.0.1:8000/ -H "traceparent: PLACEHOLDER-do-not-leak" \
    -d '{"url":"http://whoami.egress-target.svc.cluster.local:8080/"}'
{"statusCode":200,"body":"... GET / HTTP/1.1\r\nHost: whoami.egress-target.svc.cluster.local\r\n
 User-Agent: Go-http-client/1.1\r\nAccept-Encoding: gzip\r\nTraceparent: tp-test-github-token\r\n"}
```

即 actor 发的 `PLACEHOLDER-do-not-leak` 被丢弃，出集群时是 `tp-` + Secret 真值。
不带该 header 时请求照常通过、不注入（与文档语义一致）。

反向 1 —— URI 写错（把命名空间写在第一段）时 fail closed：

```console
{"statusCode":403,"body":"actor egress policy denied"}
atenet-egress 日志：
credential provider k8s.io denied: 'Client specified an invalid argument',
message: "credential URI \"ate-secret://k8s.io/ns1/example-api/token\":
path must begin with \"default\" (only local Secrets are supported), got \"ns1\""
```

→ 内置 k8s provider 只接受 `ate-secret://k8s.io/default/<ns>/<secret>/<key>` 这一种前缀。

反向 2 —— 撤掉 atespace→namespace 授权：

```console

（再 rollout restart deployment/atenet-egress）→
{"statusCode":403,"body":"actor egress policy denied"}
```

## D. 本轮新增的环境缺口

| 现象 | 处理 |
|---|---|
| `ate-setup deploy demo X` 卡在 `0/2 replicas available` | Worker 注册要求 atespace 已存在；先 `kubectl ate create atespace X` 再部署 |
| 新命名空间的 worker 起不来（`:443 bind: permission denied`） | 每个 demo 命名空间都要给 worker Deployment 补 `securityContext.sysctls: net.ipv4.ip_unprivileged_port_start=80`（worker 容器 drop 了 `NET_BIND_SERVICE`） |
| 新命名空间 worker 镜像拉取 x509 | 在该命名空间再建一份 `poc-registry-ca` ConfigMap 并挂进 worker |
| `traefik/whoami` 节点直拉失败 | `crane cp --insecure docker.io/traefik/whoami:latest 192.168.5.221:5000/traefik/whoami:latest` |
