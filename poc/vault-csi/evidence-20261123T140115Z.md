## 续测：轮转（两条路）、policy 热更新、CSIDriver 是否被 helm 重置（14:14–14:20Z）

```console
$ vault kv put secret/csi/db url=...CSI-v3-INLINE-ROT...        # 14:14:51Z
$ openshell sandbox exec vcsi-a -- cat /etc/vault-secrets/database-url
postgres://demo-app:CSI-v3-INLINE-ROT@db.tenant-a.svc:5432/app   # 路 A（PVC←静态 CSI PV）轮转 ✅，未重启
$ openshell sandbox exec vcsi-b -- cat /etc/vault-inline/database-url
postgres://demo-app:CSI-v3-INLINE-ROT@db.tenant-a.svc:5432/app   # 路 B（inline csi）轮转 ✅，未重启

# policy 闸门：/vault/secrets 不在基线里
$ openshell sandbox exec vcsi-d -- cat /vault/secrets/database-url     # 建沙箱时没给 policy
cat: /vault/secrets/database-url: Permission denied
$ openshell policy set --policy 60-policy-vault-path.yaml --wait vcsi-d
✓ Policy version 2 submitted (hash: 8b8099d295ec)
✓ Policy version 2 loaded (active version: 2)
$ openshell sandbox exec vcsi-d -- cat /vault/secrets/database-url     # 热更新之后仍然
cat: /vault/secrets/database-url: Permission denied
$ openshell sandbox exec vcsi-e -- cat /vault/secrets/database-url     # 同一个 policy，建沙箱时 --policy 给的
postgres://demo-app:CSI-v3-INLINE-ROT@db.tenant-a.svc:5432/app         # ✅
$ openshell sandbox stop vcsi-d && openshell sandbox start vcsi-d
$ openshell sandbox exec vcsi-d -- cat /vault/secrets/database-url
postgres://demo-app:CSI-v3-INLINE-ROT@db.tenant-a.svc:5432/app         # ✅ 重启后热更新的 policy 生效，CSI 卷重新挂上

# 不是 CSI 的问题，是 live sandbox 的文件策略不会热生效（普通目录同样）
$ openshell policy set --policy <base+/opt> --wait vcsi-e && openshell sandbox exec vcsi-e -- ls /opt
ls: cannot open directory '/opt': Permission denied
$ openshell policy set --policy <base 去掉 /var/log> vcsi-e
  │ read_only path '/var/log' cannot be removed on a live sandbox       # 收窄是被明确拒绝的

# helm upgrade（同 chart）不会把 CSIDriver 改回去
$ helm upgrade secrets-store csi-secrets-store/secrets-store-csi-driver --version 1.6.2 -n secrets-store --reuse-values
$ kubectl get csidriver secrets-store.csi.k8s.io -o jsonpath='{.spec.volumeLifecycleModes}'
["Ephemeral","Persistent"]
```
