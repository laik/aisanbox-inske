## 2. 本轮新踩的坑

1. **开 OIDC 之后，原来的 mTLS 客户端证书 CLI 通道不再被当作用户认证**：`openshell -g <mTLS profile> workspace list` → `missing authorization header`。chart 里 `tls.clientCa` 仍在（日志 `TLS client certificate verification enabled`），但用户侧只认 OIDC token。管理动作也要走 OIDC（用一个带 `os-admin` 的身份）。
2. **CLI 连自签证书 Gateway 必须带 `OPENSHELL_GATEWAY_INSECURE=true`**，否则每次调用都是 `connect error: transport error` —— 长得像网络故障，实际是 CLI 校验服务端证书失败。矩阵里凡不走统一 wrapper 的调用都会静默失败。
3. **Keycloak access token 默认 300s**：矩阵跑到一半就 `cached OIDC token has expired; run 'openshell gateway login …'`。realm 里设 `accessTokenLifespan: 1800` 后实测 `ttl=1800s`。
4. **issuer 证书与运行中的 nginx 裂脑**：脚本每轮重签 CA/证书 → secret 更新了，但 nginx 只在启动时读一次证书 → 客户端用新 CA 校验旧证书 → `upstream SSL certificate verify error: (7:certificate signature failure)`，在 Gateway 侧只表现为 `OIDC discovery request failed`。现在脚本只在 SAN 不匹配时重签，并在证书/realm 变化时重启 Keycloak。
5. CLI 0.1.9 没有 `auth` 子命令；无人值守登录仍可用 `gateway add --oidc-issuer` + `OPENSHELL_NO_BROWSER=1` 打出的 device URL，由 `device-approve.py` 完成授权（POC3 的 `lib-cli-login.sh` 原样可用）。
